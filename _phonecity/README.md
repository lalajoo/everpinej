# 달콤한 나의 폰도시 — 3D 산책 (1단계: 혼자 걷기)

> 내가 폰에서 보낸 시간이 작은 도시가 되고, 그 안을 직접 산책한다.

기존 SVG 시안(`reference/index.html`)의 색·문구·기능을 유지하면서 React + Three.js로 옮긴 로컬 프로젝트입니다.

## 모바일 개선 및 공개 배포 (2026-11-10)

서비스 이름: **달콤한 나의 폰도시 / My Sweet Phone City**

- 작은 화면에서 가로 넘침을 없애고 제목·닉네임·입력 폼을 정리했습니다.
- 모바일 산책·실내·옥상을 화면 전체로 표시하고 안전 영역과 방향 전환에 대응합니다.
- 조이스틱 다중 터치, 포커스 이탈, 층 변경 시 입력 끊김을 수정했습니다.
- 건물 선택 후 바로 탐험할 수 있고, 실내 시야와 로비 조작 안내를 개선했습니다.
- 리액션 후 카메라 복귀, 밤 옥상 밝기, 숨겨진 프로필 미리보기 렌더링을 개선했습니다.
- 검증: 단위 테스트 64개, 타입 검사 및 빌드 통과. 브라우저 320×568, 390×844, 740×390에서 레이아웃·입력·산책·계단·옥상·깃발·리액션을 확인했습니다. 실제 iOS/Android 기기의 터치 감도·성능은 아직 측정하지 않았습니다.
- 운영 주소: **https://everpinej.com/phonecity/**. GitHub `lalajoo/everpinej`의 `phonecity/`에서 정적 배포하며 재빌드용 소스는 `_phonecity/`에 보관합니다. 절차는 `DEPLOY.md`를 참고하세요.
- 첫 화면은 가벼운 SVG 도시로 표시하고 3D·캐릭터·OCR은 사용할 때 불러옵니다. 프로필은 첫 산책 때 정합니다.
- 폰도시 전용 GA4 `G-NV579L5P1K`(속성 **달콤한 나의 폰도시**, `563479387`)를 방문자의 동의 후에만 불러옵니다. 페누리와 별도 속성으로 집계하며, 도시 데이터·캡처·닉네임·입력 문구는 보내지 않습니다. 하단에서 동의를 철회할 수 있습니다.
- 공유는 HTTPS 서비스 주소만 전달합니다. 네이티브 공유가 응답하지 않아도 화면에서 링크를 복사할 수 있습니다. 1200×630 OG 이미지와 검색용 메타데이터를 포함합니다.
- 통계 속성 분리 후 테스트 73개와 타입 검사·빌드가 통과했습니다.
- 기존 검증 기록과 미완료 목록은 아래의 과거 작업 기록입니다.

## 건물 탐험 (2단계 MVP)
도시에서 건물 정문으로 가서 들어가고, 계단을 올라 옥상에 도착하면 바깥 풍경이 펼쳐집니다.
1. **산책하기**를 누르고 건물 정문(앞면 가운데, 처마 아래)으로 갑니다. **🚪 ○○ 타워 들어가기**(E)
2. 로비에서 빨간 안내 띠를 따라 오른쪽 계단실로 갑니다.
3. 계단에서는 **W/↑ 또는 조이스틱 위 = 오르기, S/↓ = 내려가기**, Shift 또는 ⏩ 버튼 = 빠르게
4. 맨 위층에서 **🚪 옥상 문 열기**(E): 문이 열리고 옥상으로 나갑니다. 숲·산·바다·하늘, 메시지, 배경음(끌 수 있음)
5. 옥상에서 자유롭게 걷고, 드래그·휠로 둘러봅니다. **도시로 내려가기**로 돌아옵니다.

- **층수**: `src/city/floors.ts`. 주간 사용 시간(하루 평균 × 7) 기준점 0/1/3/7/14/21시간 → 3/10/20/40/60/100층입니다. 기본은 구간 사이를 선형 보간(`mode: 'interpolate'`)하고, 표 그대로 쓰려면 `'steps'`로 바꾸면 됩니다. 외부 높이 = 0.8 + 층수 × 0.12이므로 외부 모형 높이와 내부 층수가 비례합니다.
  예시 데이터: YouTube 75F, Instagram 49F, 카카오톡 41F, Safari 25F, Spotify 22F, 기타 21F
- **계단**: 반복 모듈(한 층 = 두 줄 계단 + 층계참)을 현재 층 주변 4~5개만 렌더링합니다(100층이어도 같은 비용). 캐릭터는 계단 경로(레일)를 따라 실제 3D 위치로 움직이므로 미끄러지거나 바닥을 뚫지 않습니다. 속도는 `src/interior/config.ts`의 `stairSpeed`(6.5 → 약 2.3초/층), `sprintMultiplier`(1.8)로 조절합니다.
- **카메라**: 남쪽 위에서 내려다보는 컷어웨이 방식입니다. 머리 위 층과 카메라 쪽 벽은 숨겨 벽을 관통하거나 캐릭터를 가리지 않게 했습니다. 드래그 회전은 ±45° 범위입니다.
- **진행 저장**: `phone-city/v1/progress`에 기간(데이터 세트)별·앱별로 입장 여부, 마지막 층(체크포인트), 최고 층, 옥상 도착, 마지막 플레이 시각, 기준 기간을 저장합니다. 층에 도착할 때마다 저장하고, 다시 들어가면 "N층부터 이어서 / 1층 로비부터"를 고릅니다. 새 기간의 데이터를 입력하면 새 기록으로 시작하고 예전 기록은 남아 있습니다.
- **테마**: `src/interior/themes.ts`. YouTube는 빨간 포인트와 영상 화면, Instagram은 보라·분홍 조명, 카카오톡은 말풍선, Spotify는 이퀄라이저, Safari는 나침반입니다. TikTok·ChatGPT는 예비 테마만 있습니다. 실제 로고·브랜드 에셋은 쓰지 않았습니다.
- **배경음**: Web Audio로 만든 화음입니다(외부 음원 없음). 옥상 문을 연 뒤에만 재생되고 끌 수 있습니다.

## 스크린타임 캡처 자동 인식
- 오른쪽 **📷 스크린타임 캡처로 만들기**(또는 수정 창의 같은 버튼)로 캡처를 고르면, 이 브라우저 안에서 글자를 읽어 앱별 시간을 채웁니다.
- 인식 엔진은 tesseract.js 7(Apache-2.0)이고, 한국어·영어 데이터는 @tesseract.js-data(MIT)를 씁니다. `npm run dev`/`build` 전에 `scripts/copy-ocr-assets.mjs`가 이 파일들을 `public/ocr`로 복사하므로 **외부 CDN에 요청하지 않고**, 이미지는 업로드하거나 저장하지 않습니다(언어 데이터만 브라우저 캐시에 남음). 엔진은 캡처를 올릴 때만 불러옵니다.
- 처리 과정: 확대·이진화(연한 회색 글씨도 읽히게, 다크 모드는 반전) → OCR → `src/ocr/parseScreenTime.ts`로 앱 이름·시간 추출 → 하루 평균으로 환산합니다. iPhone의 '이름 줄 + 막대·시간 줄' 배치와 흔한 오인식을 처리합니다.
- **캡처 속 앱이 그대로 건물이 됩니다.** 많이 쓴 앱 7개는 각자 건물, 나머지는 '기타'로 묶습니다. 카테고리 합계 줄이 있으면 목록에 없는 앱의 시간도 기타에 더합니다(추정이며 화면에 표시).
- "지난 7일/일일 평균" 같은 글자가 있으면 일주일 합계로 보고 ÷7 합니다. 화면에서 하루/일주일을 바꿀 수 있습니다.
- 인식은 틀릴 수 있어서 결과를 칸에 채워 보여주고(인식/없음 표시), 확인 버튼 한 번으로 도시가 만들어집니다.
- 흔한 오인식("34분"→"345", 아이콘이 글자로 읽힘)은 보정하며 테스트로 고정했습니다.

## 앱 목록 (데이터 v2)
- `src/data/apps.ts`: 알려진 앱(YouTube, Instagram, 카카오톡, Safari, Spotify, Threads, Chrome, ChatGPT, App Store, TikTok, Netflix, 네이버, X, 메시지)은 이름 변형을 하나로 묶고 정해진 파스텔 색·아이콘·한국어 이름을 씁니다. 모르는 앱은 이름에서 만든 id·색·첫 글자 아이콘을 씁니다.
- 부지 8곳(`src/city/slots.ts`): 이름 있는 앱 최대 7개 + 기타. 앱별 자리는 `CityData.slotOf`에 기억해서, 다음에 시간이나 순위가 바뀌어도 같은 앱은 같은 자리에 있습니다. 새 앱은 중앙에 가까운 빈 자리부터 받습니다.
- 수정 창에서 앱을 추가·삭제하고 이름을 바꿀 수 있습니다. 이전 형식(v1, 고정 6개 앱) 저장값은 자동으로 v2로 옮기며 값은 그대로 유지합니다.
- 내부 테마·벽 문구: 알려진 앱은 전용, 모르는 앱은 건물 색에서 만든 테마와 공통 문구를 씁니다.

## 프로필 (닉네임·캐릭터)
- 처음 들어오면 닉네임과 캐릭터(여자/남자)를 정합니다. 닉네임은 '화면 밖으로 나가는' 콘셉트로 자동 추천되고(예: "산책하는 다람쥐", "하늘 보는 참새", 🎲로 다시 뽑기), 직접 지어도 됩니다(12자). `src/data/profile.ts`
- 캐릭터는 귀여운 2등신 스타일입니다: 큰 머리, 반짝이는 큰 눈(깜빡임), 볼터치, 웃는 입, 손·신발. 여자는 단발·앞머리·리본·원피스, 남자는 삐죽 앞머리·바보털·후드티입니다. 미리보기에서 손을 흔듭니다. `src/scene/AvatarModel.tsx`
- 닉네임은 캐릭터 머리 위 이름표, 옥상 축하·질문 문구, 깃발 서명("— 닉네임")에 쓰입니다. 헤더의 🙂 버튼으로 바꿀 수 있습니다.
- 저장: `phone-city/v1/profile`(이 브라우저에만).

## 옥상 축하·깃발·리액션
- 옥상에 처음 도착하면 불꽃놀이(입자 버퍼 하나 재사용)와 색종이가 터지고, 캐릭터가 자동으로 만세를 합니다. 이어 축하 메시지가 나옵니다.
- 이어서 "스마트폰을 내려놓고, 무엇을 하고 싶나요?"라고 묻습니다. 답(20자)은 옥상 꼭대기에 펄럭이는 깃발로 꽂히고, 진행 기록(`AppProgress.flag`)에 저장되어 도시에서도 그 건물 옥상에 작은 깃발로 보입니다. '깃발 바꾸기'로 고칠 수 있습니다.
- 리액션은 옥상에서만 쓸 수 있습니다: 🙌 만세(1), 💃 춤추기(2), 📱 폰 던지기(3). 캐릭터는 도시와 건물 안에서 계속 스마트폰을 쥐고 다니다가, 옥상에서 던지면 폰이 포물선을 그리며 날아가 땅에 떨어집니다. 다음에 건물에 들어가면 다시 손에 쥐고 있습니다.
- 리액션 시간은 프레임 시간을 누적해 계산합니다(`src/scene/AvatarModel.tsx`의 `poseAction`).

## 계단실 벽 문구
- 문구는 약 300개입니다(공통 122개 + 앱별 13~24개). 한 건물 안에서는 모두 쓰기 전까지 반복하지 않아, 100층 건물에서도 같은 문구가 다시 나오지 않습니다.
- 층마다 다른 문구 게시판이 층계참 정면 벽에 붙어 있습니다(`src/interior/messages.ts`). 홀수 층은 앱 특징 문구(유튜브: 자동 재생·알고리즘·쇼츠, 인스타그램: 피드·좋아요·비교, 카카오톡: 알림·단톡방, Safari: 탭·검색, Spotify: 음악과 산책), 짝수 층은 공통 문구입니다.
- 종류: 응원 / 잠깐!(도파민 경고) / 바깥(폰을 내려놓으면 보이는 세상) / 명언(출처 표기). 초반엔 응원, 중반엔 경고, 후반엔 바깥·명언이 많아지고, 꼭대기 층은 옥상 안내입니다.
- 새 층에 도착하면 같은 문구가 화면 위쪽에 5초 동안 자막으로도 나옵니다(모바일 가독성 대비).
- 같은 앱·층이면 항상 같은 문구이고, 연속한 층에서는 반복되지 않습니다.

## 정책
- **높이**: `h = 0.8 + 0.55·√분` 하나의 함수를 모든 건물에 적용. 엄격한 단조 증가, 클램프 없음(1440분 ≈ 21.7). 기존 240 클램프는 없앴습니다.
- **배치**: 앱 id → 고정 부지. 시간을 바꿔도 위치가 섞이지 않습니다. 0분은 나무 공원.
- **입력**: 하루 평균(분). 앱별 0–1440 정수(소수는 반올림), 합계 1440 이하. 넘으면 값을 자르지 않고 오류로 알립니다.
- **기간**: 예시 데이터는 "예시 기간" 태그를 붙여 표시하고, 직접 입력할 때는 사용자가 기간을 선택합니다(기본은 어제까지 최근 7일).
- **저장**: localStorage `phone-city/v1/city`(도시 데이터), `phone-city/v1/settings`(그래픽 품질). 캡처 이미지는 이 기기에서 미리보기만 하고 저장하거나 업로드하지 않습니다. "예시로 되돌리기"는 저장값을 지웁니다.
- **이동**: 경과 시간 기반(4.2 단위/초, dt 상한 0.1초). blur나 탭 전환 시 키·조이스틱 입력을 비웁니다.
- **가림**: 산책 중 카메라와 캐릭터 사이의 건물은 반투명하게 처리합니다.
